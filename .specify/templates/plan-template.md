## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Semantic authority**: The design keeps provider output advisory and assigns
  final `ALLOW`, `REVIEW`, and `DENY` decisions to deterministic policy code.
- **Precedence**: Hard rules are identified and cannot be weakened or overridden
  by provider signals.
- **Denial boundary**: The proxy short-circuits `DENY` before upstream dispatch,
  with a fake-server integration test that proves no call was received.
- **Explicit failure mode**: Provider/API failure behavior is typed, configurable,
  documented, audited, and covered by tests; no silent fallback exists.
- **Provider abstraction**: Semantic evaluation uses the `DecisionProvider`
  interface, with Jev-specific transport and parsing isolated from policy code.
- **Keyless verification**: Core behavior is testable with a fake MCP server and
  mock provider, without a TypeSafe API key or external service.
- **Data minimization**: Provider payload fields are allowlisted and tests prove
  that secrets, authorization headers, environment variables, and credentials are
  excluded.
- **Scope**: Work fits v0.1 MCP proxying, deterministic policy, semantic evaluation,
  audit logging, or benchmarking; excluded product features are not introduced.
- **Engineering discipline**: The design uses TypeScript strict mode, explicit
  boundary types, small focused modules, and policy/proxy boundary tests.
- **Phase gates**: Every phase ends with passing relevant tests and the full type
  check before the next phase starts.
